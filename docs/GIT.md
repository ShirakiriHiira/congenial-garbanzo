# Git 提交与代码标准

在 AI 提交至 GitHub 仓库以及本地的 Git 仓库时，请遵循下面的硬性要求：

  - Author Name 与 Committer Name 均必须为 ShirakiriHiira；Author Email 与 Committer Email 均必须使用允许的邮箱。不可以是除此之外的其余任何人，请不要加任何的 co-author。包括也禁止将 Claude、GPT 这样的模型来写为 co-author
  - 写代码时，如果在原作者的基础上进行贡献，那么必须遵循原作者的贡献特征，包括代码风格、注释语气和格式等。不要另起炉灶自成一派。记得看近期 git 历史，从这里看提交的说明、提交者的代码风格，并以这些为标准来做。提交记录里是怎么写标题和描述的，你就按照它仿写描述。提交信息首先遵循仓库近期历史。默认使用简短标题，如果找不到稳定的提交文案规范，那么在填写提交说明时，应尽量短小精悍，标题一小段，使用陈述句，达到“只通过 commit 标题就能知道这个 commit 是做什么”的效果，其他的例如正文可省略。
  - 不要过度解释你做了什么，不要在提交里写设计意图、为什么要这样、背景问题甚至用户要求复述等一看就是 AI 过头的口癖。不得添加 AI 生成说明、设计 rationale、任务复述、测试流水账。

这个提交标准仅作为当前 Agent 的会话级或本地执行约束，不要将其写入仓库或任何会被提交、推送、发布的内容中。

除非明确要求大规模重构或新内容编写，否则一概使用最小 diff 方法来进行修改，不要自作主张进行大规模重构，不要自作主张乱删之前的代码。不要在修改了一处后再添加十处检查，不要过度编程。不要在简短的小任务里设置过于繁杂的检查流程。只添加能够直接覆盖当前缺陷或需求的验证与错误处理。不得为了假想场景增加与任务无关的 fallback、兼容层、重复校验或抽象层。不因顺手、洁癖、格式统一或个人偏好修改与当前任务无关的代码；不进行无关重命名、排序、格式化、注释重写、依赖升级或文件移动。
