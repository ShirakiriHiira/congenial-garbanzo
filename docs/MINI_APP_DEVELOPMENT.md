# Mini App 开发规范

本文件是前端专项规范；业务字段与 HTTP 契约只在 `README.md` 维护，领域规则见 `docs/DEVELOPMENT.md`。

## 1. 页面结构、路由与导航

| 路由 | 页面 | 主要行为 |
| --- | --- | --- |
| `/app/` | 服务总览 | 统计、搜索、状态/类别筛选、分页、新建 |
| `/app/services/new` | 新建服务 | 通用字段；SIM 类别才显示 SIM 字段；`?category=sim` 预选 |
| `/app/services/:id` | 服务详情 | 资料、全部有效期、规则/历史入口、归档/恢复/删除 |
| `/app/services/:id/edit` | 编辑服务 | 更新通用字段；不跨 SIM/generic kind |
| `/app/services/:id/periods/new` | 新建有效期 | 名称、精度、开始/截止、可选条款 |
| `/app/periods/:id/edit` | 编辑有效期 | 截止/精度/开始/条款；处理 cycle/terms 冲突 |
| `/app/periods/:id/rules` | 提醒规则 | 添加、编辑、启用/禁用、永久删除 |
| `/app/periods/:id/renew` | 确认续期 | 显式输入新截止；条款仅参考 |
| `/app/reminders` | 提醒记录 | 状态筛选、取消任务 |
| `/app/settings` | 设置 | 时区、私聊绑定 |

使用 Telegram BackButton 与浏览器历史；有未保存修改时离开前确认。Svelte 5 runes；不引入组件库。

## 2. 核心用户流程

1. 总览 → 服务详情：统计卡显示全部/即将到期/已过期；列表行显示名称、类别、服务商、主有效期。
2. 新建服务：名称与类别必填；服务商、公开标识、管理链接、备注可空可清空；类别决定字段文案。
3. 添加有效期：名称可选；仅日期/精确时间；开始可选；条款一次性/周期性/暂不设置。
4. 续期：显示原截止、截止时刻、时区；隐藏内部周期；新截止必须晚于旧截止和当前时间。
5. 规则：显示提前天数、时刻、启用状态；不显示内部版本。
6. 删除：删除规则/有效期/服务均二次确认并列出级联范围。

## 3. 字段与类别展示

| 类别 | 服务商 | 公开标识 | 额外 |
| --- | --- | --- | --- |
| SIM/eSIM | 运营商 | 公开标识 | 卡类型、号码、国家/地区、ICCID |
| VPS/云服务器 | 服务商 | 主机名或 IP | 无 |
| 域名 | 注册商 | 域名 | 无 |
| 软件/AI 订阅 | 服务商 | 账号标识 | 无 |
| 其他/自定义 | 服务商 | 公开标识 | 无 |

- 类别为 SIM 时显示卡类型、号码、国家/地区、ICCID；其他类别隐藏。
- 列表行 SIM 显示脱敏号码；通用服务显示公开标识/服务商；ICCID 不在列表展示。
- 服务详情只显示一个状态徽标：已过期/今天到期/N 天后到期/有效；归档行降低不透明度并显示“已归档”。
- 用户可见文本不显示内部 ID、`cycle`、`revision` 或内部枚举。

## 4. 组件、状态与 API 约定

- API 客户端集中在 `web/src/lib/api/`：`client.ts` 负责请求/错误分类，`decode.ts` 严格解码，`resources.ts` 提供资源方法。写请求不自动重试。
- 表单使用 `Submitter` 防止重复提交；冲突使用 `ConflictFlow`：保留草稿、读取最新值、用户再次确认后才提交。
- 归档/恢复使用 `PATCH /services/{id}` 的 `status`；永久删除使用 `DELETE`；规则禁用使用 `PATCH enabled:false`。
- 有效期保存需要 `expected_cycle`；条款变更需要 `expected_terms_revision`；续期需要 `expected_cycle`。
- 类别内联创建/改名保留；失败保留草稿；已存服务不能跨 kind。
- 金额输入使用最小货币单位整数；切换条款模式保留金额，除非用户显式清除。
- 备注旁提示：不要保存密码、API Token 或私钥。

## 5. 移动端、反馈与状态

- 视觉：深色头部、三张统计卡、紧凑列表、双主题、吸底操作区、Telegram 安全区；只使用现有 CSS token，不写字面色值。
- 触控区不小于 44×44；在 320/375/430 CSS px 检查长名称、系统大字、刘海与底部手势；不得出现横向溢出。
- 空状态、加载、错误、只读、冲突使用现有 `AsyncState`、`ErrorBanner`、`ConfirmDialog`、`Toast`。
- 401/403 进入只读/会话失效状态，不自动重试；网络/超时错误提供手动重试。
- 搜索显式提交；筛选变化重置游标并取消旧请求；分页失败保留已加载内容。

## 7. 验收清单

- [ ] SIM：卡类型、号码、ICCID 表单与脱敏展示正确；可创建多有效期、规则并续期。
- [ ] VPS：服务商/主机名或 IP 文案正确；列表、详情、有效期、续期可用。
- [ ] 域名：注册商/域名文案正确；有效期与续期可用。
- [ ] 软件/AI 订阅：服务商/账号标识文案正确；多有效期与规则可用。
- [ ] 自定义类别：可创建、改名；服务可归属；不能跨 kind。
- [ ] 首页状态筛选包含当前服务/即将到期/已过期/未设置有效期/已归档/全部（含归档）。
- [ ] 有效期与续期页面不显示内部 cycle/revision；不显示“有效期类型”。
- [ ] 删除服务/有效期/规则均有二次确认和级联说明；取消不写。
- [ ] 409 冲突保留草稿并阻止自动重试。
- [ ] 320/375/430 宽度无横向溢出，触控区满足 44×44。
- [ ] 空状态、加载、错误、401/403 只读状态可恢复。
