# Telegram Mini App 开发规范（专项补充）

## 0. 文档定位

本文件只规定 Mini App 的页面、组件、交互、视觉、适配与前端验收。[总体开发规范](DEVELOPMENT.md)维护系统架构、数据模型、兼容边界与安全约束；[README](../README.md)是 API/Bot 精确字段、迁移、部署和实际验证记录的唯一来源。本文件不复制 API 字段清单，也不另建契约。

技术栈保持 Svelte 5（runes）+ Vite + TypeScript strict + 原生 CSS；路由为项目内轻量 History 路由，basename 固定 `/app`，Vite base `/app/`。视觉基准仍为 [`docs/miniapp.png`](miniapp.png)（深色）与 [`docs/miniapp_light.png`](miniapp_light.png)（浅色），它们是布局参考，不是业务边界。

## 1. 视觉与响应式

- 保持现有深色头部、三张统计卡、紧凑列表、状态徽标、分隔线、双主题、吸底操作区和 Telegram 安全区。
- 统计卡文案为“全部服务 / 即将到期 / 已过期”；列表标题为“我的服务”，吸底区显示“共 N 项服务”，新增按钮文案为“添加服务”。这些是当前产品文案，不再是“卡片/通信卡”定位。
- 不复刻截图的整页描边、圆角外框、480px 限宽或 16px 装饰性外边距；页面全宽，保留设备与 Telegram 安全区。
- 颜色只通过既有 CSS token 使用，组件不写字面色值。头部与统计卡在深浅主题下都保持深色底、白字；正文、背景、分隔线随主题切换。
- 统计数字分别使用主文字色、警告色、危险色。徽标优先级为已取消 → 服务端 expired → 剩余 0–7 天 → 有效；“剩余 N 天”是用户时区日历日差，不是 24 小时倍数，不据客户端时钟改写服务端状态。
- 图标沿用 Lucide（筛选、刷新、SIM/eSIM、服务动作）；可点击图标有 `aria-label`，触控区不小于 44×44。
- 在 320、375、430 CSS px 宽度检查长名称、系统大字、浏览器缩放、刘海与底部手势条；文字换行不得与动作区重叠。
- 日期按用户 `me.timezone` 展示，不能使用设备时区。金额保持整数最小货币单位，禁止浮点显示或换算。

## 2. 路由与页面

下表省略 `/app` 前缀，是前端路由，不是 Go API 路径。

| 路由 | 页面 | 主要行为 |
| --- | --- | --- |
| `/` | 服务总览 | 服务端筛选/搜索、统计、游标分页、新建入口 |
| `/services/new` | 新建服务 | 通用字段；SIM 类别才显示专属字段 |
| `/services/:id` | 服务详情 | 资料、全部独立有效期、条款、规则、续期历史 |
| `/services/:id/edit` | 编辑服务 | 更新通用字段；现存项目不能切换 SIM/generic kind |
| `/services/:id/periods/new` | 新建有效期 | 含可选约定条款 |
| `/periods/:id/edit` | 编辑有效期 | 更新有效期，可整体替换或显式重置条款 |
| `/periods/:id/rules` | 提醒规则 | 创建、修改、启用/禁用、永久删除 |
| `/periods/:id/renew` | 确认续期 | 必须显式输入新到期时间；条款仅供参照 |
| `/reminders` | 提醒记录 | 按状态筛选、取消可取消任务 |
| `/settings` | 设置 | 用户时区、私聊绑定状态 |

旧 `/sims/new` 进入服务新建并预选内置 SIM 类别。其余 `/sims/:id*` 先用旧 SIM API 验证身份，再以 `history.replace` 进入同 ID 的通用路由，避免返回循环；非 SIM ID 不得通过旧入口。公共 `/periods/*` 通过响应中的 `service_id` 返回父服务。直接刷新深链必须可用。每页需定义加载、空、部分失败、错误、返回与脏表单离开确认。

返回只使用 Telegram 原生 `BackButton`：非根路由显示，根路由隐藏，页面内不画重复返回按钮。浏览器测试模式使用浏览器返回。脏表单启用关闭确认。会话过期后保留只读内容并禁用写操作。

## 3. 总览、搜索与筛选

- 首页直接使用服务端 overview 的 `counts`、`primary_period` 和 items；不得在客户端重选主有效期、重算统计或只筛选已加载项。
- 搜索框显式提交（按钮或 Enter）；类别和状态筛选立即请求。每次条件变化重置游标、取消过期请求，并保留现有请求序号保护，避免旧响应覆盖新条件。
- 后续分页沿用同一组筛选，直到 `next_cursor` 为 null；清空条件恢复全量首页。
- 当前 FilterSheet 暴露的 UI 选项：`active`、`due_soon`、`expired`、`no_period`、`archived`。归档仅在选择后出现。API 还支持 `all`，但当前 UI 没有“全部状态”选项；不得宣称已实现该入口。
- counts 是完整匹配集统计，与 limit/cursor 无关。筛选激活时明确显示状态，不展示“仅筛选已加载”之类的局部结果。
- 首页行显示服务名称、SIM 类型或类别、服务商及主有效期。SIM 副行优先脱敏手机号、服务商、地区；通用副行使用公开标识、服务商、类别。无未取消有效期显示“未设置有效期”。归档行降低不透明度并显示“已归档”徽标。

## 4. 服务表单与详情

名称与类别必填。服务商、公开标识、管理链接和普通备注可为空并可清除。类别可在表单内创建或改名本人类别；取消或失败必须保留服务草稿。新草稿可在类别 kind 间切换且保留未提交 SIM 字段；generic 提交不带 SIM 字段。现存项目禁止跨 SIM/generic kind 编辑。

SIM 表单保留实体 SIM/eSIM、号码、地区、ICCID；服务商标签显示“运营商”。手机号默认脱敏，ICCID 只在编辑表单出现。通用详情展示类别、服务商、公开标识、管理链接、备注与独立有效期；管理链接以 `noopener noreferrer` 打开，不做账号集成。备注只存普通说明，明确不存密码、API Token 或私钥。

详情支持归档/恢复与二次确认永久删除。归档不是删除；永久删除确认必须列出级联范围并说明不可恢复。删除成功后刷新统计并返回有效父页。服务可以没有有效期，此时显示明确空态。

每个有效期显示类型、可选名称、本地日期/时间、状态徽标、cycle 和条款；操作入口包括编辑、续期和永久删除。Mini App 不提供“取消有效期”动作。

## 5. 条款、有效期与续期交互

有效期表单提供一次性、周期性、自定义条款。recurring 需正整数周期次数与 `day/week/month/year` 单位；金额使用整数最小货币单位控件，必须与三位大写币种成对。文案固定为“约定费用/约定条款”，不得暗示已付款、自动续费或自动推进日期。

- 条款整体替换；新有效期 revision 从 1 开始。
- 修改条款提交最新 `terms.revision` 作为 expected terms revision；409 保留草稿并要求读取最新值后人工复核，不自动重试、不覆盖。
- 切换 mode 为 custom 只清除周期数量/单位；**金额和币种会保留**，除非用户明确清除。
- 无法精确显示为 JavaScript 安全整数的已有金额不得四舍五入回写；此时表单显示“重置约定条款”按钮，将条款设为 custom、金额/币种发送 null，并携带最新 expected revision。保留空白可保存非条款资料；修改条款须重新填写金额和币种或使用该重置动作。不得只因切换 mode 就静默清空金额。
- terms-only 修改不改变 cycle，不使规则、任务或续期对话失效。若同时修改截止与条款，分别使用 cycle 和 terms revision。
- 非 SIM 隐藏 SIM 有效期类型并提交 `custom`；SIM 保留原四种类型。有效期名称可空，显示回退“有效期”，不得把显示标签持久化为名称。
- 修改截止或精度按既有规则增加 cycle；规则内容变化增加 revision。所有写操作使用最新响应中的版本。
- 续期页面展示旧截止、本地日期、cycle 与作为参考的约定周期/费用；新截止必须由用户填写且晚于旧截止与当前时间。不得用条款金额填充实际付款历史。201 显示成功，200 显示“同周期相同续期已提交，已载入原记录”。

## 6. 共用交互与错误

- 表单区分“未修改”和“显式清空”；失败后保留输入。提交中禁用按钮并阻止重复写入，成功后以服务端响应覆盖本地实体。
- 读请求失败只由用户手动重试；写请求绝不自动重放。
- 401：顶部持久横幅，停止重试，进入只读，提示重新打开 Mini App；不得伪造或刷新 `initData`。
- 403 显示无访问权限；404 显示资源不存在或不可访问；400 显示字段/表单错误；413 提示内容过长；415 视为客户端缺陷；503 手动重试；500 通用错误，不展示内部细节。
- 409 必须重新拉取最新实体并让用户看到版本变化；草稿保留，禁止静默重试或本地覆盖。
- 列表部分失败时已取得数据照常展示，缺失聚合标记“统计不完整”，不伪装为 0。
- 手机号、ICCID、备注、initData、Authorization 不得进入 console、错误上报、URL、localStorage、sessionStorage 或截图。管理链接只能是绝对 HTTP(S) 且不含内嵌凭据。

## 7. 组件与工程边界

使用通用组件，例如 `ServiceList`、`ServiceRow`、`ServiceForm`、`ServiceDetail`、`PeriodForm`；共用 `FilterSheet`、`MoneyInput`、`DatePrecisionInput`、`DateTimeInput`、`ConfirmDialog`、`AsyncState`、`ErrorBanner`、`Toast` 等既有控件，不另建平行组件体系。

组件只通过 props 接收数据，不自行发请求；跨页仅共享 session（`me`、initData、主题）与显式传入数据。ID 保持 string，金额保持整数，不使用 `any` 或非空断言。API 客户端统一 `/api/v1`、注入 `Authorization`、10 秒超时、`AbortController`、204 不解析 body、错误映射；不自动重试写请求。未知响应字段忽略。

主题唯一来源是 `Telegram.WebApp.colorScheme`，监听 `themeChanged` 写入 `data-theme`；非 Telegram 环境回退 `prefers-color-scheme`。首帧前内联设置主题与背景，避免白闪。不提供手动主题开关，不跟随 `themeParams` 换色。

## 8. 本地测试、构建与安全边界

- 自动化：在 `web/` 执行 `npm ci && npm run check && npm run test && npm run build`。本次实际结果为 180 tests 通过、svelte-check 零错误零警告、生产构建完成。
- 真实业务联调：`./scripts/test-miniapp.sh`，UI `http://127.0.0.1:5180/app/`、API `127.0.0.1:8088`，临时 SQLite、真实 Service/Storage、无 Bot 轮询或 Telegram 投递。测试数据包含旧 SIM/eSIM、临期、过期、归档、空名样本，以及 VPS、订阅、域名、自定义类别、服务端创建的续期历史。
- 仅独立 `cmd/miniapp-test` 提供 `GET /__test/init-data`；前端须同时满足开发构建和 `VITE_MINIAPP_TEST_MODE` 才读取。业务请求仍走正常签名、时效和白名单；生产无测试路由或鉴权绕过。
- 生产静态资源与 API 同源，由 nginx/HTTPS 代理提供；Go 不托管静态文件。`/app` 301 到 `/app/`，SPA 回退限定 `/app/*`，不得全局兜底。

## 9. 验收

视觉与布局：

- 320/375/430 宽度保持全宽、安全区和参考层级；无截图描边或限宽。
- 深浅主题 token 完整；统计、列表、徽标、chevron、吸底区和分隔线一致；头部与统计卡不随浅色反转。
- 仅原生 BackButton 返回；图标、触控区、长文本与秒级时间显示正确。

功能：

- 旧 SIM 新建/编辑及全部原有效期类型可用；通用 VPS/订阅/域名/自定义类别可创建、搜索、分页。
- 类别内联创建/改名失败不丢草稿；已存项目不能跨 kind；管理链接安全打开。
- 搜索显式提交；类别与五种状态筛选作用于全量结果；清空恢复全量；归档仅在对应筛选出现。
- 条款可创建、整体替换、切换 mode 保留金额，并通过“重置约定条款”显式清空；持久化的 int64 最大费用也可安全重置为 custom/null，不四舍五入。双标签页制造 terms/cycle/rule 冲突时，409 保留草稿且不覆盖。
- 续期必须输入新截止，201/200 反馈正确，约定费用不自动成为付款。
- 归档/恢复与永久删除清晰区分；删除二次确认列出级联范围，404/409 不误报成功。
- 旧 SIM 深链验证身份后 replace 到通用页；通用服务和有效期深链刷新可用，无返回循环。
- 手机号默认脱敏、ICCID 只在编辑出现；无秘密字段，敏感值不进入日志、URL、存储或截图。
- 401 只读、无重试风暴；重复点击不产生重复写请求。

工程：

- `npm run check`、`npm run test`、`npm run build` 通过；无 `any`、无 UI 组件库、无未使用依赖。
- 生产构建及运行进程无测试身份入口；`./scripts/test-miniapp.sh` 可在无真实 Token 时运行。
- 浏览器验收不能替代真实 Telegram 投递、iOS/Android 原生 WebView/返回、HTTPS 部署。缺少外部凭据或设备时明确记为未验收。

## 10. 实施与提交

先完成 API 客户端/路由/列表现有主流程，再完成通用表单、条款与冲突、旧深链和响应式验收。提交前检查 diff 并运行相关测试；不自动 commit、amend 或改写历史。提交格式沿用根 README 的 `type: concise English description`。
