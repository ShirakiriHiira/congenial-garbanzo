# Mini App 开发规范

本文件规定了 Mini App 的前端开发规范。后端 API 契约见 [API.md](API.md)，领域逻辑见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 1. 路由与导航

| 路径 | 功能 | 核心行为 |
| :--- | :--- | :--- |
| `/app/` | 服务总览 | 统计、筛选、新建服务 |
| `/app/services/new` | 新建服务 | 根据类别 (`sim`/`generic`) 展示动态字段 |
| `/app/services/:id` | 服务详情 | 资料、有效期列表、操作入口 |
| `/app/services/:id/edit` | 编辑服务 | 修改基本信息 |
| `/app/services/:id/periods/new` | 新建有效期 | 设置日期、续费条款 |
| `/app/periods/:id/edit` | 编辑有效期 | 处理周期冲突 |
| `/app/periods/:id/rules` | 提醒规则 | 管理提醒规则 |
| `/app/periods/:id/renew` | 确认续期 | 确认新截止时间 |
| `/app/reminders` | 提醒记录 | 查看与取消任务 |
| `/app/settings` | 设置 | 时区、会话、绑定设置 |

> [!IMPORTANT]
> - 使用 Telegram `BackButton` 和浏览器历史堆栈。
> - 离开有未保存修改的页面时，必须触发确认提示。

## 2. 核心操作流程

1. **总览**: 统计卡显示总览；列表行展示简要状态。
2. **新建服务**: 必填名称与类别，依据类别动态显示字段（如 SIM 细节）。
3. **有效期管理**: 支持手动设置或根据有效天数推算截止；续费信息可选。
4. **续期**: 必须显式确认新的截止时间。
5. **级联删除**: 所有删除操作必须经过二次确认，并明确告知影响范围。

## 3. 类别、字段与脱敏显示

| 类别 | 标识字段展示 | 敏感数据处理 |
| :--- | :--- | :--- |
| **SIM** | 卡类型、脱敏号码 | ICCID 绝对不展示 |
| **VPS/云** | 主机名/IP | 无 |
| **域名** | 域名 | 无 |
| **订阅** | 账号标识 | 无 |

- **原则**: 用户界面不可出现任何内部 ID、`cycle`、`revision` 或枚举值。
- **状态徽标**: 仅显示过期、临期或已归档状态，降低归档项视觉优先级。

## 4. 技术实现原则

- **架构**: API 客户端位于 `web/src/lib/api/`，包含请求分类、解析和统一的资源方法。
- **表单**: 使用 `Submitter` 防重复提交。
- **冲突处理**: 采用 `ConflictFlow`，冲突发生时保留本地草稿并拉取服务端最新数据，用户确认后再提交。
- **数值处理**: 金额输入采用小数，提交前根据 ISO 4217 规则转换为最小单位整数。

## 5. 视觉与移动端适配

- **视觉**: 使用统一的 CSS Token，杜绝字面色值；深色/浅色双主题支持。
- **触控**: 触控区域必须满足 ≥ 44×44 CSS px。
- **响应式**: 在 320/375/430px 视口下检查长名称溢出，杜绝横向滚动。
- **状态复用**: 必须统一处理空状态、加载中、报错、只读、网络中断等状态。

## 6. 测试与截图

- **固定截图**: `test_screen/` 目录下包含所有关键流程截图（主页、详情、新建、续期、设置等）。
- **截图安全**: **绝严禁**包含真实敏感数据（Token、initData、真实号码等）。
- **回归测试**: 必须覆盖五类服务场景及错误恢复路径。

## 7. 验收清单

- [ ] 五类服务类别字段展示与校验正确。
- [ ] 首页筛选功能 (`active`, `due_soon`, `expired`, `archived` 等) 准确。
- [ ] 删除操作二次确认与影响范围说明。
- [ ] 409 冲突处理及草稿保留机制可用。
- [ ] 响应式布局 (320px-430px) 无溢出。
